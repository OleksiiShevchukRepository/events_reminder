# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state

This repo holds a Telegram reminder bot that is specified but not built. There is no application code, so there are no build, lint or test commands yet, and no language, storage or hosting has been chosen. Those choices belong to `/speckit-plan`. Add the real commands and architecture here once they exist.

## Workflow

Development follows Spec Kit, run through the `/speckit-*` skills in `.claude/skills/`:

`/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` → `/speckit-implement`

- `.specify/` and `.claude/skills/` were generated by the `specify` CLI (0.12.18) with the Claude integration and PowerShell scripts.
- This project deliberately has no constitution. The constitution files and `/speckit-constitution` were removed, and `/speckit-plan`, `/speckit-analyze` and the plan template were edited to match. Re-running `specify init` would restore them.

To confirm that Spec Kit can resolve the active feature:

```powershell
.\.specify\scripts\powershell\check-prerequisites.ps1 -Json -PathsOnly
```

## Active feature

- Work happens on `main`, not on a feature branch. The scripts find the feature through `.specify/feature.json`, which points to `specs/001-telegram-reminder-bot`, so they fail without that file.
- The script output reports `BRANCH` as `001-telegram-reminder-bot`. That is the feature's name, and no such git branch exists.

## Reading the spec

`specs/001-telegram-reminder-bot/spec.md` is the source of truth for behavior.

- The `Input` line quotes the original request and is out of date. Where they differ, the Clarifications section and the requirements take priority.
- The original request's "custom date range" is called "custom interval" everywhere else: a start date plus every N days.
